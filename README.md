# 澄心瑜伽 · 私教全流程管理（体验课测评 / 排课 / 续费提醒 / 书面延期 / 转教练）

城市瑜伽馆私教业务的一体化页面：**会员、顾问、教练** 三个角色围绕 **同一套训练记录** 协作 ——
从体验课预约、教练测评、购课排课，到每节课的课后记录、请假改期、不适上报、换教练与续费跟进，
每一次疼痛、缺勤、训练效果和课程调整都会沉淀为后续排课与续费沟通的依据。

**课包临近过期续费沟通（本主题）**：会员剩余三节课且两周后到期时，页面结合**出勤、请假、训练效果与教练建议**生成续费提醒；
会员因工作原因无法按期完成时，顾问可发起**书面延期或调整上课频率申请**，审批通过后课包日历**自动重排**剩余课程；
所有承诺写入课包记录，防止口头延期争议；会员继续请假时，页面明确提示已延期次数与合同规则，顾问不能无限口头承诺。

- 技术栈：Vue 3 + TypeScript + Pinia + Vue Router + Vite（纯前端 SPA，数据存 localStorage，可一键重置演示数据）
- 项目类型：前端（无后端业务接口，故不提供 Swagger/OpenAPI）

## 快速启动

### 方式一：Docker（一键）

```bash
docker compose up --build
# 打开 http://localhost:8080
```

也可手动：`docker build -t yoga-pt-studio . && docker run -p 8080:80 yoga-pt-studio`

### 方式二：本地开发

```bash
npm install
npm run dev        # http://localhost:5173
```

### 生产构建与预览

```bash
npm run build      # 类型检查 + 构建到 dist/
npm run preview    # http://localhost:4173
```

## 验证方式（建议演示路径）

1. **体验转化**：顾问登录 →「安排体验课」为李敏选教练（介意异性 → 仅显示女教练，按目标推荐）→ 教练苏晴/林岚登录 → 周课表点体验课 → 填课后记录 → 填测评（体态评估/动作限制/课程建议/风险提示/推荐套餐，提交即锁定）。
2. **购课排课**：会员张倩登录 → 主页确认购买推荐套餐 → 自动生成课包、每周排课、请假规则与续费提醒基线。
3. **上课记录**：教练林岚登录 → 周课表点王晓彤的待上课 → 填完成动作/体感/疼痛变化/家庭练习 → 下节课重点自动同步。
4. **异常闭环**：
   - 会员王晓彤 →「请假与申请」上报膝盖不适 → 教练林岚在会员档案中做「课程调整」→ 顾问在「异常工单」办结；
   - 教练周远在周课表点「请假」→ 顾问在工单中为何静的课改期补课；
   - 会员孙悦申请换教练 → 顾问在工单中选择新教练 → 历史测评与全部课后记录完整交接（新教练视角可见同一份档案）。
5. **续费提醒（四要素）**：顾问登录 → 看板「续费提醒」→ 进入赵磊的会员 360°：顶部卡片结合
   **出勤**（9 节全勤/出勤率）、**请假记录**、**训练效果**（体感、疼痛趋势、最近一课）、**教练建议**（测评课程建议/推荐套餐，只读引用）生成提醒，
   并给出「课包日历测算」：当前每周一 1 次，到期日前只能完成 2 节，第 3 节超出有效期 → 明确提示续费 / 书面延期 / 调整频率三选一。
   点「✨ 基于训练记录生成要点」可把上述事实写入沟通纪要。
6. **书面延期与日历自动重排**（赵磊，密码 123456）：
   - 在会员 360°「延期 / 调整上课频率」卡片看到合同规则（最多 2 次、单次 ≤14 天、累计 ≤30 天，口头承诺无效）；
   - 选择「仅延期」7 天、填写工作原因（如"年底项目冲刺加班"）→ 提交后进入**待审批**，提交前可看到**重排预览表**（原日期 → 新日期、自动改期/仍超期标记）；
   - 点「审批通过」：课包有效期即时顺延，课包日历自动重排剩余待上课（仍在有效期内的课保留原日期，超出有效期的课自动前移到最早空档），承诺写入课包「书面承诺记录」并同步到三方共享的训练时间线；
   - 继续发起第 2 次申请时选择「延期并调整频率」（如周一改为周一+周三）：审批后排课计划切换、课表整体按新频率重排；若新日历仍排不下，预览与时间线会明确提示剩余超期节数，不静默处理。
7. **合同上限与后续请假提示（防止无限口头承诺）**：
   - 赵磊课包延期 2 次后，申请区显示「已达合同上限」，顾问无法再提交延期（单次超 14 天、累计超 30 天同样会被拦截并提示原因）；
   - 用何静登录（她已有 1 次书面延期）→「请假与申请」：页面提示本月请假次数、请假规则，以及「已延期 1/2 次、累计 7/30 天，口头承诺不作为延期依据」，下方可见她本人的书面延期凭证；
   - 顾问端「待处理请假」对会员请假同样展示该课包的延期次数与合同规则，引导顾问走书面流程而非口头答应。
8. **边界**：顾问在会员 360° 看到的教练专业档案为只读锁定卡（🔒），不可编辑；教练的测评与风险提示不会变成销售话术；延期申请被驳回时课包有效期与课表不变，驳回原因留档。
9. 右上角「重置演示数据」可随时恢复初始场景。

## 实际执行过的验证

- `npm run build`（vue-tsc 类型检查 + vite 构建）通过；
- 针对本主题编写了临时端到端脚本（Pinia store + 种子数据，在 Node 中运行，验证后已删除），**37 项断言全部通过**，覆盖：
  - 种子场景：赵磊剩 3 节 / 14 天到期，且按每周一频率至少 1 节排在有效期外；
  - 续费提醒四要素（出勤率 100%、日历测算 gap=1、教练建议、平均体感 8/10）；
  - 延期申请校验：单次 >14 天拦截、原因为空拦截、同课包重复待审批拦截；
  - 审批通过：有效期顺延、书面承诺写入课包、待上课均落入新有效期、时间线留痕；
  - 合同上限：2 次后第 3 次申请被拒；何静累计 7 天后第 2 次 14 天可过、再申请被拒；
  - 驳回：有效期与课表不变、驳回原因留档；
  - 调整频率：排课计划切换为每周 2 次、课表自动重排；
  - 重排纯函数：仅延期时保留原位+补位、排不下时标记超期；提频后全部落入有效期。
- `npm run preview` 启动后 `curl http://127.0.0.1:4173/` 返回 200（见下方验证记录）；
- Docker 镜像构建与容器运行未在本环境执行（环境无 Docker 守护进程），Dockerfile 采用标准 node 构建 + nginx 静态服务多阶段方案。

## 目录结构

```
src/
  types/index.ts        # 领域模型（预约/测评/课包+延期规则/排课/记录/工单/续费/延期申请/时间线）
  data/seed.ts          # 演示种子数据（赵磊剩3节14天到期；何静已有1次书面延期）
  utils/date.ts         # 日期工具 + 课包日历重排算法（relayoutSessions/upcomingDates/到期测算）
  stores/               # Pinia：auth（登录）+ data（业务动作、续费四要素、延期申请/审批/自动重排）
  views/
    member/             # 预约体验课、我的主页（课包/课表/购课）、训练记录、请假与申请（延期次数/合同规则提示）
    coach/              # 周课表、会员档案、课后记录、体验测评
    consultant/         # 经营看板、安排体验课、异常工单、会员 360°（四维续费提醒+书面延期/调频率）
  components/           # 训练时间线（三方共享）、专业档案（锁定只读）、课包卡（延期记录与合同规则）
```
