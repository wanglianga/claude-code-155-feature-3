# 澄心瑜伽 · 私教全流程管理（体验课测评 / 排课 / 续费 / 延期 / 转教练）

城市瑜伽馆私教业务的一体化页面：**会员、顾问、教练、店长** 四个角色围绕 **同一套训练记录** 协作 ——
从体验课预约、教练测评、购课排课，到每节课的课后记录、请假改期、不适上报、换教练与续费跟进，
每一次疼痛、缺勤、训练效果和课程调整都会沉淀为后续排课与续费沟通的依据。

**本题重点：课包临近过期续费沟通闭环**

- 会员剩 3 节课、两周后到期时，顾问在「续费沟通」页看到由 **出勤、请假、训练效果、教练建议** 生成的续费提醒与沟通要点；
- 会员因工作原因无法按期完成时，顾问可发起 **延期 / 调整上课频率申请**，由 **店长审批**（口头承诺无效）；
- 审批通过后 **课包日历自动重排剩余课程**，所有承诺 **写入课包承诺记录**（会员/顾问/店长可见同一份），防止口头延期争议；
- 合同规则硬性约束：**每课包最多延期 2 次、单次 ≤30 天、累计 ≤45 天**，超限系统自动拦截；会员后续再请假时，页面会提示已延期次数与合同规则。

- 技术栈：Vue 3 + TypeScript + Pinia + Vue Router + Vite（纯前端 SPA，数据存 localStorage，可一键重置演示数据）
- 项目类型：前端（无后端业务接口，故不提供 Swagger/OpenAPI）

## 快速启动

### 方式一：Docker（一键）

```bash
docker compose up --build
# 打开 http://localhost:8080
```

也可手动：`docker build -t yoga-pt-studio . && docker run -p 8080:80 yoga-pt-studio`

### 方式二：本地开发

```bash
npm install
npm run dev        # http://localhost:5173
```

### 生产构建与预览

```bash
npm run build      # 类型检查 + 构建到 dist/
npm run preview    # http://localhost:4173
```

### 业务逻辑冒烟测试（无需浏览器）

```bash
npm run smoke      # 24 项断言：延期申请→审批→自动重排→合同规则拦截
```

## 验证方式（建议演示路径）

1. **体验转化**：顾问登录 →「安排体验课」为李敏选教练（介意异性 → 仅显示女教练，按目标推荐）→ 教练苏晴/林岚登录 → 周课表点体验课 → 填课后记录 → 填测评（体态评估/动作限制/课程建议/风险提示/推荐套餐，提交即锁定）。
2. **购课排课**：会员张倩登录 → 主页确认购买推荐套餐 → 自动生成课包、每周排课、请假规则与续费提醒基线。
3. **上课记录**：教练林岚登录 → 周课表点王晓彤的待上课 → 填完成动作/体感/疼痛变化/家庭练习 → 下节课重点自动同步。
4. **异常闭环**：
   - 会员王晓彤 →「请假与申请」上报膝盖不适 → 教练林岚在会员档案中做「课程调整」→ 顾问在「异常工单」办结；
   - 教练周远在周课表点「请假」→ 顾问在工单中为何静的课改期补课；
   - 会员孙悦申请换教练 → 顾问在工单中选择新教练 → 历史测评与全部课后记录完整交接（新教练视角可见同一份档案）。
5. **续费沟通（本题核心）**：顾问登录 → 看板「续费提醒」→ 赵磊「续费沟通」→ 页面结合出勤（9/12 节）、请假、训练效果（体脂降 2.1%、体感趋势、最近教练备注）与教练建议生成沟通要点 → 保存跟进。
6. **延期申请 → 审批 → 自动重排（本题核心）**：
   - 顾问在赵磊的续费沟通页 →「延期 / 调整上课频率申请」：工作原因、延期 14 天、勾选调整频率（如周一+周四）→ 提交店长审批；
   - **店长王店长登录** →「延期审批」→ 查看合同规则校验（0/2 次 → 1/2 次）→「批准并重排日历」；
   - 回到顾问续费沟通页 / 会员赵磊主页：课包到期日 +14 天、剩余 3 节已按新频率自动重排、「课包承诺记录」中新增延期承诺（时间线同步可见），课包到期工单自动办结。
7. **合同规则拦截（本题核心）**：
   - 顾问进入何静的续费沟通页 → 已延期 2/2 次，申请入口被拦截并提示合同规则（顾问不能无限口头承诺）；
   - 会员王晓彤（已延期 1 次）→「请假与申请」→ 请假页顶部提示已延期次数与合同规则；
   - 会员赵磊主页「课包承诺记录」与顾问端看到的是同一份，口头承诺无效。
8. **边界**：顾问在会员 360° 看到的教练专业档案为只读锁定卡（🔒），不可编辑；教练的测评与风险提示不会变成销售话术。
9. 右上角「重置演示数据」可随时恢复初始场景。

## 目录结构

```
src/
  types/index.ts        # 领域模型（预约/测评/课包/排课/记录/工单/续费/延期申请/承诺记录/时间线）
  data/seed.ts          # 演示种子数据（覆盖六类异常 + 延期三档场景：未延期/已延 1 次/达上限）
  stores/               # Pinia：auth（登录）+ data（全部业务动作、合同规则校验与看板计算）
  views/
    member/             # 预约体验课、我的主页（课包/课表/承诺记录/购课）、训练记录、请假与申请
    coach/              # 周课表、会员档案、课后记录、体验测评
    consultant/         # 经营看板、安排体验课、异常工单、会员 360°、续费沟通（提醒/延期申请/承诺）
    manager/            # 延期审批（合同规则校验、批准自动重排日历）
  components/           # 训练时间线（三方共享）、专业档案（锁定只读）、课包卡、课包承诺记录
scripts/
  smoke.ts              # 业务逻辑冒烟测试（npm run smoke，node 直跑 Pinia store）
```
